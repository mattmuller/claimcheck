# claimcheck bench

This benchmark tests a tool that takes a written claim about software containing a number with a time unit (for example "Cached thumbnails expire after 10 minutes.") and must find the line of code that sets that value. `fixture/` is a small fake TypeScript service (logging, cache, rate limiter, uploads, jobs, backups, webhooks, reports, health checks, plus `config/` files and SQL migrations). `claims.json` lists the claims, each with `gold`: the line(s), relative to the repo root, whose number you would change to make the claim false. `gold` is empty for claims the code does not address. It was written without seeing the search code, so it is not tuned to how the tool works.

Kinds: `direct` number and unit sit together (`LOG_RETENTION_DAYS = 90`). `wording` the claim uses different words than the identifiers. `converted` the code uses another unit or raw milliseconds (`300`, `7_200_000`, `5 * 60 * 1000`). `derived` the value is built from named constants defined in another file (`10 * MINUTE`). `config` the value lives in a .json/.yaml/.env.example file and code only reads it. `env-default` the value is the fallback in `process.env.X ?? 900`. `sql` the value is in a migration (interval, cron schedule). `distractor` the same number appears in several unrelated places and only one is right. `absent` the code never sets the thing; gold is `[]` and the tool should report no match. `wrong` the code sets the thing to a different value, so the claim is false; gold is the line that sets it.
